### 技术坑点（务必记住）
1. **刷新 token 必须用裸 `Taro.request`**，不能走 `request.ts`：
   否则 `request → tokenManager → request` 循环依赖，且刷新请求自身 401 会递归。
2. **Supabase refresh_token 滚动失效**，用掉即作废。并发请求同时 401 时若各自刷新，
   只有第一个成功、其余把用户踢下线。`tokenManager.refresh()` 用共享 Promise 单飞解决。
3. **网络错误绝不清会话**：只在 `ApiError.isAuthError`（401/token 类错误码）时登出，
   否则后端没启动或断网时用户会被反复强制退出。
4. pydantic `EmailStr` **拒绝 `.local` 等保留域名**（422）。
   `scripts/make_user_token.py` 里的 `verify@jbsttj.local` 走不了 `/auth/login`。
5. Supabase 也会拒绝 `example.com` 注册（`email_address_invalid`）。

## 登录响应处理增强（用户给了真实 Supabase 登录响应，要求"合理处理"）

- **新增 `src/utils/jwt.ts`**：手写 base64url + UTF-8 解码（小程序无 `atob`/`Buffer`，三端通用），
  暴露 `decodeJwt` / `getJwtExpiryMs`。已用真实 token 对比标准 Buffer 解码，结果**完全一致**。
- **`tokenManager.toSession` 改用 JWT 的 `exp` 作为过期基准**：
  `expiresAt = getJwtExpiryMs(access_token) ?? Date.now()+expires_in*1000`。
  原因：`expires_in` 依赖客户端收到响应时刻折算，受网络耗时/时钟漂移影响；JWT 的 `exp`
  是服务端权威绝对时间，续签更准。解码失败自动回退 `expires_in`。
- **`pickUser(raw, accessToken)`**：id/email/role 由「响应 user 对象 > JWT claims」互为兜底；
  新增 `emailVerified`（取 `user_metadata.email_verified` 或 `email_confirmed_at`）。
- **`authStorage.AuthUser` 加 `emailVerified?: boolean`**。
- **`doRefresh` 修正**：刷新时 `next.user = this.session?.user ?? next.user`，
  避免用 JWT 里占位的 `role:"authenticated"` 覆盖 `/auth/me` 拿到的真实业务角色（此前 pickUser
  返回 null 才保留旧 user，现在 pickUser 能从 claims 造 user，故必须显式优先保留现有）。
- **`store/auth.tsx` refreshUser**：`/auth/me` 回写时保留 `emailVerified`、email 缺省沿用旧值。
- 顶层 `user.role` 恒为 Supabase 的 `authenticated`（Postgres 角色，非业务角色），仅占位。

## 后端服务端口管理（运维）

- 后端 `jbsttj-backend` 用同一份代码、不同 PORT 跑过多个实例：8000（.env 默认）+ 8010 +
  8020，另有一个多余的 `uvicorn --port 8010` 显式实例。前端 `API_ORIGIN=127.0.0.1:8010`，
  故 **8010 是前端实际对接的开发口**。
- 关闭端口 = `taskkill /F /PID <pid>`（注意 Git Bash 里用单斜杠 `/F`，双斜杠 `//F` 会被拒）。
  进程命令行通过 `Get-CimInstance Win32_Process -Filter "ProcessId=..."` 拿。
- Windows 强制杀进程后，`netstat -ano` 会**短暂残留**死 PID 的 LISTENING 条目（进程已真死，
  以 `tasklist` 为准）；新绑定通常不受影响。
- 重启（默认重启到 8010）：`cd jbsttj-backend && PORT=8010 .venv/Scripts/python.exe run.py`
  （DEBUG=true → uvicorn reload，会多一个 reloader 子进程）。
