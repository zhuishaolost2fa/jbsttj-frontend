# 2026-08-08

## ScriptSubmitForm 底部按钮点不到（mask 点击却能取消）Bug 修复

现象：DM 指南导入后弹出的「剧本信息」底部弹层，点底部「确认并提交/取消」无反应，
但点遮罩（mask）能触发取消。

根因（布局，非事件）：
- 弹层是 flex 列（header / body / footer），外层 `max-height:88vh; overflow:hidden`，
  `.sf-body { flex:1; overflow-y:auto }` 但**缺 `min-height:0`**。
  flex 子项默认 `min-height:auto` 不收缩到内容高度以下，表单字段多（约 14 个）时
  body 撑高，把 footer 挤出 88vh 被 `overflow:hidden` 裁掉 → 按钮渲染在可交互区外，
  点到空白处实际落在 mask 上 → 表现为「按钮无反应、mask 能取消」。
- 另：`handleSubmit` 里残留一个 `debugger;`（开发期会暂停执行），已删除。

修复：
1. `index.less` 的 `.sf-body` 加 `min-height: 0;`（flex 滚动标准修法），body 收缩并可内部滚动，footer 常驻可见可点。
2. `.sf-footer` 加 `position: relative; z-index:1; background:#fff;` 防御性防遮挡。
3. 删掉 `handleSubmit` 内的 `debugger;`。

验证：tsc `src/` 0 错误。对比 `ImportDmGuide` 同款 `<Button onClick>` 模式可正常工作，
确认事件写法没问题，问题只在布局裁切。

注：NutUI `Button` 用 `onClick` 即可（项目内 ImportDmGuide 已验证）；自定义遮罩靠
sheet 上 `e.stopPropagation()` 阻止冒泡到 mask，事件写法本身正确。

## NutUI Button (nutui-react-taro ^2.6.14) H5 onClick 行为（已读源码确认）

- `Button` 在 H5 下 onClick **正常工作**：`handleClick(e){ if(!loading&&!disabled&&onClick) onClick(e) }` 挂在原生 `<button onClick>` 上，无 H5 专属禁用。
- **真坑 1**：H5 下 Button 默认 `type="submit"`（nativeType/formType 都未默认，HTML `<button>` 默认 submit）。若包在 `<form>` 里点击会触发表单提交（刷新/跳转），看似 onClick 没跑。修复：显式传 `nativeType="button"`。本项目弹层非 `<form>`，不适用。
- **真坑 2**：`disabled` 或 `loading` 为真时 `handleClick` 直接 return，回调不执行（如 submitting 卡 true / 误传 loading）。
- **真坑 3**：被遮挡/裁切（本次实际原因）——点到的根本不是 Button，而是下面的 mask。
- 排查法：onClick 首行 `console.log`，有日志=Button 正常(问题在布局/逻辑)，无日志+禁用态=坑2，在 form 内+跳转=坑1。

## 用户复现：底部按钮在可视区、但 Button onClick 不触发，改成 Text 后触发

结论（读 `node_modules/@nutui/.../button.taro-*.js` + 其 CSS 确认）：
- 按钮「可见」≠「可点」。NutUI `Button` 在 Taro H5 渲染为**原生 `<button type="submit">`**
  （源码 `getEnv()==="WEB" → rest.type = rest.formType`，nativeType 未传→默认 submit）。
- 我之前给提交按钮绑了 `loading={submitting} disabled={submitting}`：
  **原生 `<button disabled>` 浏览器规范下根本不派发 click 事件**（disabled 静态属性，非仅 CSS），
  所以只要 `submitting` 为 true，点击就完全没反应——而 `<Text>` 是普通 Taro 元素无 disabled 语义，
  点击照常触发，正好对应用户现象。
- 修复（保留 NutUI 样式）：提交/取消按钮加 `nativeType="button"`（干掉 submit 默认）；
  去掉 `disabled={submitting}`；用 `submittingRef` (useRef) 防重复提交，只在 `loading` 上做视觉反馈。
- 验证：tsc `src/` 0 错误。
- 经验：Taro H5 里凡 NutUI `Button` 不触发 onClick，优先查 `disabled`/`loading` 绑定 + 是否漏 `nativeType="button"`；
  也可以直接用 `View`/`Text`（已验证可点）替代 Button 做底部操作条。

## 底部按钮最终方案：改用 View（用户拍板）

用户确认「取消 / 确认并提交」都从 NutUI `Button` 改为 `View`（避开原生 `<button>` 事件问题），
确认按钮用**迷圈黑调 `#1a1a2e`**（= 全局主色，标题/登录/首页一致），取消用浅色描边 `#f4f5f8`+`#e3e6ee` 次级。

改动：
- `ScriptSubmitForm/index.tsx`：footer 两个 `<Button>` → `<View className="sf-btn ...">`；
  确认按钮 `onClick` 内 `if(submitting) return` + `is-loading` 态显示「提交中…」；删除 `import { Button }`；
  注意：Taro `View` **类型里没有 `hoverClassName`**（只有 hoverStartTime/StayTime），按下态改用 CSS `:active`。
- `ScriptSubmitForm/index.less`：`.sf-btn` 统一样式（flex:1 / 高44 / 圆角22 / `:active` 降透明度 / `.is-loading` pointer-events:none），
  `.sf-btn--confirm` 黑底白字 `.sf-btn--cancel` 浅底描边。
- 验证：tsc `src/` 0 错误。

注：项目全局主色 = `#1a1a2e`（迷圈黑），做新 UI 时统一引用此值，不要再用 NutUI 默认红 `#fa2c19`。
