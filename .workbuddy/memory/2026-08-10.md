## 报错排查：pickDmGuideFile is not defined
- 现象：点击「导入 DM 指南」报 `ReferenceError: pickDmGuideFile is not defined`。
- 根因：非代码 bug，是 **Taro watch 的 HMR 陈旧**——重命名导出后旧 `filePicker` 模块仍在跑，新名无绑定。
- 验证：`tsc --noEmit` src 0 错误；`npm run build:h5` 成功（BUILD_EXIT 0，952 modules）。
- 解决：重启 dev/watch 服务 + 硬刷新即可。无需改代码。
- 经验：Taro/H5 重命名导出后要提醒用户重启 dev server，避免 HMR 陈旧误报。

## 新增 tabBar 菜单 + 我的剧本 + DM 手册 AI 问答
- **架构调整**：单页 → 三 tab（`导入` / `我的剧本` / `我的`）。`src/app.config.ts` 加 tabBar，纯文字不配 iconPath（省一套图标资源，避开两端路径解析差异）。
- **新增页面**：`pages/scripts`（我的剧本列表 + 解析状态）、`pages/scriptDetail`（详情 + AI 问答）、`pages/profile`（账号，从首页顶部账号条迁移而来）。
- **新增服务层**：`src/services/dmGuide.ts` —— DM 手册接口封装 + **两级问答分流**（核心）。
  - `askScriptQuestion()`：先 `GET /dm-guide/search` 向量检索；QA 相似度 ≥ `DIRECT_ANSWER_THRESHOLD`(0.82) 直接返回手册原答案（`source=manual`，零 LLM 开销）；否则才 `POST /dm-guide/ask` 调大模型（`source=ai`）。
  - 降级：ask 返回 404/405/401 时不抛错，退化成纯检索结果展示（检索已成功，不该弹报错框）。
- **后端契约**（由并行会话同步实现，本会话未改后端）：
  - 我的剧本 = `GET /scripts?mine=true`（**不是** /scripts/mine）；mine 时后端放开 status 过滤，草稿/下架本人可见。
  - `GET /scripts/{id}/import-status`：三阶段（upload/parse/ready）归一进度，轮询这一个即可。
  - `POST /scripts/{id}/dm-guide/ask`：**需登录**；`GET .../dm-guide/search`：公开。未登录时前端传 `allowLlm:false` 退化为纯检索。
- ⚠️ **字段风格不一致的坑**：`/scripts` 列表出参是**蛇形**（ScriptItem），而 `/scripts/byname` 是**驼峰**（ScriptItemCamel）。`services/script.ts` 加了 `normalizeScript()` 只翻一层 key 统一成驼峰（不递归，否则会破坏 `extra.dmGuide.objectKey`）。
- 进度展示刻意**不做全局百分比**：四阶段耗时差两个数量级，线性插值会长时间卡住像死机；只在当前阶段内算子进度 + 显示阶段名（`jobStageProgress()`）。
- 轮询策略：仅当存在 parsing/uploading 项时起表（5s），全部落定自动停；列表状态请求用 `mapLimit(…, 4)` 限并发（微信小程序并发上限 10）。
- 验证：`tsc --noEmit` src **0 错误**；`npm run build:weapp` 成功，dist/app.json 的 tabBar 正确落盘。

## 优化：import-status 调用次数收敛（N 次 → 1 次）
- **问题**：「我的剧本」列表页对每个剧本单独调 `GET /scripts/{id}/import-status`，有 N 个解析中的本就是 N 次/轮，不合理。
- **修复**：后端新增**批量状态接口** `GET /scripts/import-status?ids=id1,id2,...`（逗号分隔字符串，最多 100 个），返回 `{ scriptId: ImportStatus }` 映射。
  - 落点：`app/api/v1/scripts.py` 的 `batch_import_status()`，**必须注册在 `/{id_or_code}` 详情路由之前**，否则会被 `/scripts/{id}` 捕获（Starlette 按注册顺序匹配，字面量路径需先于路径参数）。
  - 入参用逗号字符串而非 `List[str]`，以兼容任意请求库的数组序列化行为；后端 `split(',')` + 去重 + 截断 100。
  - 单个剧本异常静默跳过（`except Exception: continue`），不拖垮整批。
  - 复用已有的 `DMGuideService.get_import_status(script)`。
- **前端**：`services/dmGuide.ts` 新增 `fetchImportStatusBatch(ids: string[])`（空数组直接返回 {}，不发请求）；`pages/scripts/index.tsx` 的 `loadStatuses` 改为一次批量调用，并删除原 `mapLimit` 辅助函数与逐本 `fetchImportStatus` 调用。列表页只传 `hasGuide=true` 的剧本 id（无手册的永远是 no_guide，无需轮询）。
- 详情页 `pages/scriptDetail/index.tsx` 仍用单本 `fetchImportStatus(id)`（只查一个本，合理），未改动。
- 验证：`py_compile` 后端 OK；`tsc --noEmit` src 0 错误；`npm run build:weapp` 成功。
