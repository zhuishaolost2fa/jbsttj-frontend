## 修复「编辑资料」点击后 URL 变了但页面不跳转
- 根因：`pages/profile/edit` 与 `pages/profile/security` 两个页面文件此前未创建，且 `src/app.config.ts` 的 `pages` 里没有注册这两条路由。点击 `Taro.navigateTo` 只把 URL 推入历史，路由表中无对应组件 → 不渲染。
- 已补齐：edit/security 两页的 `.tsx` / `.less` / `.config.ts`，并在 `app.config.ts` 注册路由（`pages/profile/edit/index`、`pages/profile/security/index`）。
- 经验（重要）：Taro H5 新增页面后**必须重启 `npm run dev:h5`** 才会重新读取 `app.config.ts` 并编译新路由；dev server 中途改 `pages` 列表不一定热更新。仅改 URL 不渲染是典型「路由未注册 + 页面文件缺失」现象。
- 校验：`tsc --noEmit` 新页面 0 错误；`taro build --type h5` 通过（967 模块）。

## 头像上传：前后端统一为后端中转 simple_upload
- 问题：前端走「presign + 直传 OSS PUT + PATCH 落库」三步走，后端 `POST /auth/me/avatar` 却是服务端 multipart 存储，且兜底字段名 `avatar` ≠ 后端 `file`，前后端不匹配、CORS/公开域名/V4 签名都易踩坑。
- 改法：统一到 `simple-upload` 服务端中转。
  - 后端 `auth.py`：`upload_avatar` 改为复用 `FileService.simple_upload`（新增 `prefix` 参数，头像传 `"avatars"`），落库 `avatar_url + avatar_object_key + avatar_color=null`；**删除** `avatar_presign` 接口与 `AvatarPresignResponse`。
  - 后端 `files.py` `get_avatar`：改从 `profiles.avatar_object_key` 回源（老数据回退 `avatars/{user_id}`）。
  - 后端 `repository.py` `list_by_user`：过滤 `avatars/*`，头像不进文件列表。
  - `profiles` 新增列 `avatar_object_key`（`sql/profile.sql` 的 `do $$` 块，需重跑 SQL）。
  - 前端 `services/auth.ts` `uploadAvatar`：改为直接 multipart POST 到 `POST /auth/me/avatar`（字段名 `file`），删除 presign/直传/兜底逻辑；`constants/auth.ts` 删 `avatarPresign`。
- 校验：后端 5 个文件 py_compile 通过；前端 src 仅剩一处与本次无关的预存错误（store/auth.tsx 未用 `Profile` 导入）。
