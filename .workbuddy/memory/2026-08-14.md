# 2026-08-14

## Bug fix: 删除 PDF 后重传同名 docs，解析状态仍显示 PDF

- 根因：DM 指南走 `temporary` 上传（temp/ 前缀，OSS 7 天生命周期）。剧本删除不立刻清底层文件对象；后端按文件名（或文件名+大小）做秒传去重时，先传 `山鬼母.pdf` 删除后再传同名 `山鬼母.docx` 会 `instant=true` 命中旧 PDF 的 file 记录。`ossMultipartUpload.ts` 在秒传命中时直接采用 `init.file.filename` 作为 fileName，导致解析状态文件名错显为 PDF、且拿旧文件解析。
- 修复：`src/utils/ossMultipartUpload.ts` 的 `multipartUploadToOss`。秒传命中后校验命中文件扩展名与本地所选扩展名是否一致；不一致则放弃秒传、不带 `file_hash` 重新 `initUpload` 强制真实上传当前文件。`init` 改为 `let` 以支持二次 init；新增 `getFileExt` 辅助函数；`initParams` 提为具名变量便于重调。
- 防御点：扩展名是类型硬标识，跨格式命中即视为误命中。同格式同内容真·秒传不受影响。
- 注意：`src/components/ScriptSubmitForm/index.tsx:200` 残留一个 `debugger;` 语句（疑似调试遗留），与本次 bug 无关，未改动。
