## 后端地址改为环境变量配置（Vercel 友好）
- `src/constants/api.ts`：`API_ORIGIN` 改为 `process.env.TARO_APP_API_ORIGIN || 默认地址`（默认仍是 https://jbsttj-backend-production.up.railway.app），删除原来 prod/dev 两个分支（值本就相同）。
- **关键坑**：Taro 4.x Vite 模式下，`TARO_APP_*` 前缀变量只从 `.env` **文件**注入（`@tarojs/helper` 的 `dotenvParse` 只 parse 文件，不读 shell env）。Vercel 控制台设的是 shell 环境变量，默认不会进产物——直接用 `process.env.TARO_APP_API_ORIGIN` 会被编译成裸标识符（undefined），走默认值。
- 解决：`config/index.ts` 的 `defineConstants` 里，仅当 `process.env.TARO_APP_API_ORIGIN`（构建期 shell 变量）有值时显式 `JSON.stringify` 注入；无值时不定义，让 .env 机制或代码默认值兜底。优先级：shell(CI) > .env 文件 > 默认值。
- 新增 `.env.example` 文档化 `TARO_APP_API_ORIGIN`。
- 验证：设 shell 变量构建→测试 URL 进产物且覆盖默认值；不设→回退默认值。两种均通过。
- Vercel 部署：在 Project Settings → Environment Variables 加 `TARO_APP_API_ORIGIN`=<Railway 后端域名>，重新触发部署（构建期注入）。
