### 修复：重播不生效（重启后无 ?t=）
- **根因 1（致命）**：图标 `<img>` 元素自身带 class `weui-tabbar__icon`（见 `node_modules/@tarojs/components/dist/components/taro-tabbar.js` 第 53 行 `h("img",{src:iconPath,class:'weui-tabbar__icon'})`），不是包在 `.weui-tabbar__icon` 容器里。原选择器 `.weui-bar__item_on .weui-tabbar__icon img` 永远匹配不到 → 直接 return，所以根本没加 `?t=`。
- **根因 2（竞态）**：直接改 `img.src` 会被组件重渲染覆盖（src 绑定到 state 的 `selectedIconPath`，render 第 333/53 行），不可靠。
- **修正**：`replayActiveTabIcon.ts` 改为用正确选择器 `.weui-tabbar__item.weui-bar__item_on img` 取选中项，读其 `img.src` 作为 base（去掉旧 `?t=`），再调用官方 `Taro.setTabBarItem({ index, selectedIconPath: base + '?t=' + Date.now() })`。该值进入 tabBar 组件 state（`setTabBarItemHandler` 第 217-235 行），重渲染后 img.src = 新 URL → 浏览器重请求 → SMIL 重播，且因走 state 不会被覆盖。H5 的 `setTabBarItem` 会原样透传 `selectedIconPath`（taro-h5/dist/api/ui/tab-bar.js 第 145-152 行）。
- `useDidShow`（= `componentDidShow`）在 H5 切 tab 时确实会触发（plugin-framework-react/dist/runtime.js 第 697-708 行，router 切换触发 ONSHOW），生命周期挂法没问题。
- 验证点：切到「剧本」「我的」时，选中图标每次都重新描边出现；浏览器 Network 里应能看到带 `?t=` 的 svg 请求。

## dev:h5 被 build:h5 误伤修复（21:50）
- 前因：favicon 功能把 `build:h5` 改为 `taro build --type h5 && node scripts/copy-favicon.js`，而 `dev:h5` 是 `npm run build:h5 -- --watch`，npm 把 `--watch` 追加到整条命令末尾（落在 copy-favicon.js 上），导致 dev:h5 变成一次性构建、无 watch 无热更。
- 修复：`dev:h5` 改为直接 `taro build --type h5 --watch`，不经 build:h5 转发；build:h5 保留 favicon 拷贝尾巴（仅生产构建需要）。
- 教训：npm run 传参会追加到整条 shell 命令末尾，含 `&&` 链的脚本不能作为带参转发的目标。
