# 2026-08-26 工作日志

## 修复微信小程序 tabBar 图标格式错误
- 问题：`app.config.ts` 的 tabBar iconPath/selectedIconPath 引用了 `.svg` 文件，微信小程序只支持 `.png/.jpg/.jpeg`，构建报错。
- 修复：将 4 处引用从 `.svg` 改为 `.png`（tab-scripts / tab-profile 各 普通态 + active 态）。
- 经验：H5 端 SVG 图标可用，但微信小程序 tabBar 不支持 SVG，必须用 PNG；项目 `src/assets/tabbar/` 下同时保留了 SVG 和 PNG 两套，小程序构建只能引用 PNG 版本。

## 修复微信小程序 `process is not defined` 运行时崩溃
- 症状：构建通过但启动即抛 `ReferenceError: process is not defined`，栈顶在 common.js/app.js 模块加载处。
- 根因：`config/index.ts` 的 `defineConstants` 只在 shell 环境变量存在时才定义 `process.env.TARO_APP_API_ORIGIN` / `TARO_APP_ARMS_ENV`；本地无 `.env` 文件且 shell 未设置时，这两个引用原样残留进产物，小程序运行时没有 `process` 全局对象 → 崩溃。
- 修复：`config/index.ts` 新增 `loadEnvFile()`（手动解析根目录 .env，忽略注释/空行），无条件 `defineConstants` 注入两个常量，三级优先级 shell > .env > 代码默认值（默认值与 src/constants/api.ts、src/monitor/arms.ts 保持一致）。原理依据：@tarojs/vite-runner/dist/mini/config.js 中 `Object.assign({}, envConstants, defineConstants)`，用户 defineConstants 覆盖 Taro 的 .env 注入。
- 验证：`NODE_OPTIONS=` 清空后 `npm run build:weapp` 成功，产物 grep `process\.` 为 0，API_ORIGIN 内联为字面量。
- ⚠️ 沙箱限制记录：WorkBuddy 环境通过 NODE_OPTIONS 注入 genie-safe-delete shim，Taro 构建时 `emptyDirectory` 清空 dist 会逐文件失败（trash 二进制报 "Some operations were aborted"，疑似文件被微信开发者工具占用 + shim 干扰）。**解法：`NODE_OPTIONS= npm run build:weapp`**（剥离 shim，Node 原生删除构建产物目录）。此前记忆里的"失败后直接重跑"对 weapp 不生效，只有清 NODE_OPTIONS 稳定可行。

## 小程序端「导入 DM 指南」改为引导去 H5（web-view 内嵌）
- 新增页面 `src/pages/webview/index.{tsx,less,config.ts}`：顶部提示条（💡 请在下方 H5 页面登录后导入 + 「复制链接」按钮兜底）+ `<WebView src>` 加载 `https://jbs-ttj.store`（默认值，支持 ?url= 参数覆盖）；`onError` 时提示「请检查小程序后台是否配置 jbs-ttj.store 为业务域名」。

- ⚠️ 微信小程序 web-view 只能加载业务域名白名单内的站点：需在小程序后台「开发-开发管理-开发设置-业务域名」配置 `https://jbs-ttj.store`，否则白屏（有复制链接兜底）。
- 验证：tsc src 0 报错；`NODE_OPTIONS= npm run build:weapp` 成功；dist 含 pages/webview 四件套、app.json 已注册、profile/index.js 含跳转与域名。
