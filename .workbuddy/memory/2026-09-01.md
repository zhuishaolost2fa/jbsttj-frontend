## 踩过的坑（重要）

1. **Taro 不会把 `src/static/` 拷到 `dist/`**（与既往记忆相反）。OG 图必须靠 `gen-seo-pages.mjs` 构建后兜底拷贝 → 统一引用 `/static/og-image.png`。
2. **后端 `/scripts` 的 `limit` 上限 < 200**（传 200 返 422），必须分页（limit=50 循环）。`/dm-guide/stories` 同理。
3. **列表页会产生 32 个 404**：45 部剧本里只有 13 部生成了内容页。修法 —— `hrefOf(s)`：`hasGuide` 才链 `/s/{code}/`，否则链 SPA 路由 `/#/pages/scriptDetail/index?code=xxx`。改完用脚本扫全站 `href` 验证 0 死链。
4. **`src/index.html` 的 HTML 注释里不能嵌套 `<!--`**，否则注释提前结束。
5. 变量遮蔽：`const jsonLd = jsonLd({...})` 会遮蔽同名工具函数，已改名 `ldBlocks`。
6. resvg 的 SVG 属性：`font-family=${JSON.stringify(FONT)}` 会给属性值再套一层双引号，必须写 `font-family="${FONT}"`。
7. `gui-he-nu-fang` 的 qa-titles 响应慢（~30s+），脚本需带重试 + 并发控制。

## IndexNow 双端点推送修正（22:10，commit fb66939）

原实现是「api.indexnow.org 优先 + 失败时回退 bing.com」，问题是 **Bing Webmaster 后台的 IndexNow Insights 报表只统计走 `www.bing.com/indexnow` 的提交**，聚合端点的提交不计数，导致后台一直显示 "get started"。

改为**两个端点都推送**（不再「成功即停」）：
- `www.bing.com/indexnow` → 让 BWT 的 IndexNow Insights 记录到
- `api.indexnow.org/IndexNow` → 协议聚合端点，分发给 Yandex / Seznam / Naver / Yep

重复提交幂等。全量重推一次两个端点均 HTTP 200。

## 环境坑

- **本机 curl 访问外网会走沙箱代理**（`https_proxy=http://127.0.0.1:61148`），代理抖动会造成 `code=000` 假超时，看起来像站点挂了。判断线上是否真的故障要用 `curl --noproxy '*'` 对照。Node 的 fetch 同理，必要时加 `NO_PROXY='*'`。
- **git push 偶发 "access rights" 报错**，重试一次通常即可成功（同样与代理抖动相关）。
