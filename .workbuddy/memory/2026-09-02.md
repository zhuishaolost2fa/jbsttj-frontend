## 放开小程序端导入 DM 手册（双通道上传）

需求：小程序端原先被硬编码成「跳 web-view 打开 H5 导入页」，现放开，因为 doc 文件一般 < 10MB。

- `src/utils/filePicker.ts`：新增 `PickedFile` 抽象（H5 有 `File`，小程序只有 `path`）+ `pickChannel()` / `maxSizeOf()`；`pickDmGuideFile()` 增加小程序分支 `Taro.chooseMessageFile`；`validateDmGuideFile` 按通道取不同上限（H5 500MB / 小程序 20MB）。
- `src/utils/simpleUpload.ts`（新）：小程序上传引擎，`Taro.uploadFile` → `POST /files/simple-upload`，`upload_type=temporary`；`onProgressUpdate` 驱动真实进度，`AbortSignal` 转接 `UploadTask.abort()`；stage 序列与分片链路对齐以便复用五步指示器。

- 删除 `src/pages/webview/` 页面 + `app.config.ts` 路由（死代码）。

### 后端（jbsttj-backend）

### 已验证的事实（别再重复查）
- **FastAPI 静默忽略未声明的 multipart form 字段**（实测 200，非 422）→ 前后端可分开发布：前端先发也只会退化为落永久前缀，不会报错。
- 后端配置对 .doc/.docx 放行：`ALLOWED_EXTENSIONS` 为空（未启用白名单，只走黑名单），黑名单仅 `exe,bat,cmd,sh,com,scr,msi,dll,jar`；`MAX_FILE_SIZE=5GB` ≥ simple-upload 的 20MB 上限。`temp_upload_prefix=temp`。

### 健壮性细节（别在后续重构时删掉）
- `simpleUpload.ts` 里 `tokenManager.getAccessToken()` 返回 null 时**必须提前抛错**：`Taro.uploadFile` 不走 `services/request.ts`，没有 401 重放与会话清理，硬发只会拿到用户看不懂的 401。
- 已确认 `getAccessToken()` 在 token 临期（<5 分钟）时**会先续签再返回**，所以上传发起时 token 一定新鲜；401 只可能源于会话真的失效。
- 微信/Taro 的失败是 `{ errMsg }` 普通对象而非 Error 实例，必须转成 Error，否则上层 `err?.message` 取不到值、只能显示兜底文案。另外把 `url not in domain list` 翻译成「上传域名未加入小程序白名单」。
- `remainSeconds` 无法估算时传 **-1**（渲染成 `--`），别用 0 —— 上传刚开始速度没测出来时会显示荒谬的「剩余 0 秒」。

## 后端 simple-upload 改动的实证（11/11 通过）

之前只验证了「FastAPI 忽略多余 form 字段」，没验证**加了 `upload_type` 后逻辑真的生效**。补做了 service 层验证，脚本保留在
**`jbsttj-backend/scripts/check_simple_upload_prefix.py`**（改 simple_upload 后可重跑回归）：

```
PYTHONPATH=. ./.venv/Scripts/python.exe scripts/check_simple_upload_prefix.py
```

用假 OSS + 假 Repository 打桩，不碰真实 DB/OSS。⚠️ 必须设 `PYTHONPATH=.`，否则 `No module named 'app'`（运行脚本时 sys.path 加的是脚本所在目录 scripts/，不是 cwd）。

覆盖与结果：
| 用例 | 结果 |
|---|---|
| `prefix=temp` → object_key 落 `temp/` | PASS |
| `prefix=None` → 落默认 `uploads/` | PASS |
| 同内容跨前缀**不**复用（永久对象不会被临时上传秒传命中） | PASS |
| 同前缀内重复内容命中秒传（不再 put 对象） | PASS |
| 秒传查询确实带 `key_prefix=temp` | PASS |
| 20MB 上限 / 空文件 / `.exe` 黑名单 | PASS |
| `.doc` `.docx` 放行 | PASS |

关键实现细节（别在重构时改错）：
- `find_by_hash` 的前缀过滤是 `object_key like {key_prefix}/*`，**prefix 不能带尾斜杠**（带会变成 `temp//*` 匹配失败）。API 层传的 `settings.temp_upload_prefix` 值是 `"temp"`，正确。
- `simple_upload` 里 `prefix or self.settings.upload_prefix`——API 层 temporary 传 `"temp"`、permanent 传 `None`，靠这行落到默认 `uploads`。

## API 层验证（7/7 通过）+ 端到端 URL 核对

脚本保留在 **`jbsttj-backend/scripts/check_simple_upload_api.py`**，用 TestClient + `dependency_overrides` 打桩 `get_current_user` / `get_file_service`，不发真实请求：
```
PYTHONPATH=. ./.venv/Scripts/python.exe scripts/check_simple_upload_api.py
```
| 用例 | 结果 |
|---|---|
| `upload_type=temporary` → service 收 `prefix='temp'` | PASS (HTTP 201) |
| `upload_type=permanent` → `prefix=None` | PASS |
| 不传 → 默认 permanent | PASS |
| 非法值 → **422** `invalid_upload_type`，且不调用 service | PASS |
| `filename` 覆盖 / 回退到上传文件名 | PASS |
| service 收到 `max_size=20MB` | PASS |

⚠️ 两个坑：
- **别用 `with TestClient(app)`**：会触发 lifespan，去连 Supabase。不用 with 即可跳过。
- **FastAPI 0.141.1 的 `include_router` 在 `app.routes` 里放的是 `_IncludedRouter` 占位对象（延迟展开），没有 `path` 属性**——遍历 `app.routes` 取不到任何业务路由路径。改用 `app.openapi()["paths"]` 拿最终路径。

**端到端 URL 核对**：前端 `buildApiUrl(API_PATH.simpleUpload)` = `{API_ORIGIN}/api/v1/files/simple-upload`，与后端 OpenAPI 里的真实路径 `/api/v1/files/simple-upload` 完全一致 ✅。

**小程序 `chooseMessageFile` 契约已核对**（Taro 类型定义 + 微信官方文档）：
- 返回 `tempFiles[].{name, path, size, type, time}` —— 代码里取 `name/size/path` 正确
- `extension?: string[]`（**基础库 2.6.0+**，低版本该参数被忽略，所以 `validateDmGuideFile` 的后缀校验不能省）
- `type: 'file'` 语义是「除图片和视频之外的文件」，且 `extension` 仅在 `type=='file'` 时生效 —— 当前传法正确
- 文档未给出取消时的 errMsg 原文，代码用 `/cancel/i` 宽松匹配，够用

### 已知取舍
- **两条链路的秒传不互通**：H5 分片链路存的是前端算的**抽样** SHA-256，simple-upload 由后端算**全量** SHA-256，同一文件跨端会各存一份对象。影响有限（同一用户跨端重复传同一文件不多），要修得统一哈希算法。
- 小程序端拿不到「是否命中秒传」标记，`UploadResult.instant` 恒 false。

### 待办 / 部署注意
- ⚠️ 小程序后台需把后端域名加入 **uploadFile 合法域名**（不只是 request 合法域名）；代码里已把微信的 `url not in domain list` 翻译成「上传域名未加入小程序白名单」提示。
- 后端改动需重新部署（Railway）后 `upload_type=temporary` 才生效。
