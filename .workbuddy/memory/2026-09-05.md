### 改动

1. **修虚假 lastmod**（`scripts/gen-seo-pages.mjs`）
   - 问题：首页与 `/scripts/` 用 `todayISO()`，每次构建都刷新。Google 会忽略这种「不携带信息量」的
     lastmod，严重时整个字段被降权。内容页用 `script.updatedAt` 是对的，保留。
   - 方案：引入内容指纹 + 持久化缓存。
     - `fingerprint(parts)` = sha256(JSON) 前 16 位
     - `stableLastmod(cache, key, fp)`：指纹未变复用上次日期，变了才推进到今天
     - 首页与剧本库共用 `collectionFp`（剧本 code + updatedAt + hasGuide 序列）
     - 内容页缺 `updatedAt` 时回退到指纹缓存
     - 缓存文件 `.seo-lastmod-cache.json`（已加 gitignore，同 `.indexnow-cache.json`）
   - 顺带把首页/剧本库 `changefreq` 从 daily 改成 weekly（真实更新频率就是周级，解析一部手册才变）。
   - 验证：连跑两次 `gen:seo`，sitemap 的 lastmod 完全一致。

2. **新增 `llms-full.txt`**（513 KB）
   - llms.txt 只有 37 行索引清单，AI 读完知道「该去哪」但还要二次抓取；
     llms-full.txt 把问答对正文（answer 截断 600 字符）+ 故事还原（截断 1500 字符）直接铺开，省掉二次抓取。
   - 数据源是 `details` 里已有的 qa/stories（不额外发请求，不拖慢构建）。注意 `qa` 已被
     `slice(0, MAX_QA_PER_SCRIPT=200)` 截断，文件里如实标注「共 N 条，本文件收录前 M 条」。
   - `llms.txt` 的「内容说明」里加了全文版链接。
   - **故意不把 llms-full.txt 放进 sitemap**：IndexNow 的 URL 来源就是 sitemap 的 `<loc>`，
     推进 Google 索引反可能被判低质量页。它给 AI 抓取器用即可（`/llms.txt` 是约定路径，抓取器会主动找）。

### 顺带修掉一个存量 bug：首页 JSON-LD 累积

发现过程：为了验证 lastmod 稳定性，我单独连跑了 3 次 `npm run gen:seo`（不经 taro build），
发现 `dist/index.html` 的 `application/ld+json` 块数 3 → 5 地在涨。

根因：`enhanceSpaIndex()` 的旧清除正则是「`SEO:HOOK` 到第一个 `<script<%=` 或 `<script\s`」，
但注入内容自己就含 `<script type="application/ld+json">`，于是正则在**第一个 JSON-LD 处就停了** ——
每次只清掉 meta 部分，JSON-LD 块全部残留后再注入一份新的。

为什么之前没暴露：正常流程走 `build:h5`，taro 每次重建 `dist/index.html`，产物是干净的；
只有单独反复跑 `gen:seo` 才会累积。

修法：注入内容用显式 `<!-- SEO:BEGIN -->` / `<!-- SEO:END -->` 包裹，清除时按这对标记精确匹配；
保留兜底（无 BEGIN/END 的历史产物清到 `</head>` 之前），且兜底只在检测不到 BEGIN 时才跑。

验证（直接判据）：连跑 3 次 `gen:seo`，JSON-LD 恒为 3 块，两个验证标签始终保留。
线上（Vercel 重新构建后）也是 3 块，title / canonical 正常。

## ⚠️ 线上白屏事故与修复（commit 3ae43d0）

**事故**：上一版为修 JSON-LD 累积，把兜底清除改成「`SEO:HOOK` 一路清到 `</head>`」。
但那段区间里还有 Taro 注入的 `<script src>` 和 CSS `<link>` —— 一并清掉后 SPA 拿不到 JS，
线上整页白屏，body 只剩 `<div id="app"></div>`。用户发现后报错。

**根因**：我的验证只覆盖了 meta / JSON-LD / 站点验证标签，**没有验证 SPA 的 JS 入口是否还在**。
这正是 IDENTITY.md 里写着的那个弱点（拿间接证据当结论）的又一次发作 —— 数了 JSON-LD 块数
就以为产物完整，没去确认「页面能不能真的跑起来」这个最终判据。

**修复**：
1. 兜底清除改为逐类精确匹配「我们自己注入过的标签」，其余内容一律不碰
2. 新增安全护栏：注入后若检测不到带 `src` 的 `<script>`，直接中止写入，
   **宁可不产出也绝不产出白屏页面**

**验证（直接判据）**：
- 构建产物：JS 入口 1 个、CSS link 3 个、JSON-LD 3 块、两个验证标签各 1 个、`#app` 挂载点在
- 幂等：连跑 2 次 `gen:seo`，上述计数全部不变
- 线上：JS 入口 `/js/app.b9f6434e.js` 返回 200，各项计数与本地一致

**教训（已写入 MEMORY.md 第五节）**：凡是改 `enhanceSpaIndex()`，验证清单必须包含
`grep -o '<script[^>]*src=' dist/index.html`。HTML 注入类改动不能只看自己注入的东西在不在，
要看**被改动的文件的完整性有没有被破坏**。
